# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ina is a community link-sharing site modelled on reddit's r2: communities live at `in/{name}`,
moderators are called *innkeepers*, and AutoModerator is called *Bouncer*. It deliberately keeps
r2's URL scheme, form field names (`uh` for the CSRF modhash, `api_type=json`), fullnames
(`t1_…` comment, `t2_` account, `t3_` link, `t4_` message, `t5_` community) and API JSON shapes.
When behaviour is ambiguous, "what r2 did" is usually the intended answer. Licensed AGPL-3.0-only.

Stack: Python 3.13, Litestar + Jinja2, SQLAlchemy (async, Core tables, not ORM) on Postgres,
Alembic, Redis, Dramatiq on RabbitMQ, OpenSearch, S3-compatible storage (SeaweedFS locally),
vanilla JS/CSS in `static/`. Tool versions are pinned in `mise.toml`.

## Commands

All tasks are mise tasks (`mise tasks` lists them):

```sh
mise run setup          # uv sync + install pre-commit and commit-msg hooks
mise run services       # docker compose up: postgres, redis, rabbitmq, opensearch, seaweedfs, mailpit, traefik
mise run migrate        # alembic upgrade head (dev database)
mise run seed           # sample data, then rebuild karma and search; `mise run reset` wipes first
mise run dev            # litestar run --reload on :8000 (Traefik serves it on http://localhost)
mise run worker         # dramatiq app.jobs
mise run check          # the CI gates: lint (ruff check + format --check), typecheck (mypy), biome, test
```

CI also runs `uv run djlint --check --lint app/templates`, which `mise run check` does not include.

Tests need the compose services running. A single test:

```sh
uv run pytest tests/controllers/test_marks.py::test_name
uv run pytest -k bouncer
```

New migration (autogenerated from `app/repos/pg/tables.py`):
`uv run alembic revision --autogenerate -m "add something"`.

Site admins are granted only from the shell: `uv run python -m scripts.admins grant NAME`.

## Architecture

### Request path

`app/main.py` builds the app. Handlers are plain Litestar functions in `app/controllers/`, and
**every handler must be listed in `ROUTES` in `app/main.py`** to be served. A route is closed to
OAuth API apps unless it is also given a scope in `app/controllers/scopes.py`.

Layers, top down:

- **controllers**: parse input, fetch things, call services, return a view. Dependencies are
  injected by name using the `*Dep` aliases in `app/controllers/deps.py`; repositories are built
  per request from the request's DB session. `viewer` is the signed-in account or `None`; `user`
  requires one.
- **services** (`app/services/`): domain rules (permissions in `perms.py`, ranking, Bouncer,
  etc.). They take repository *Protocols* as arguments and never import an implementation.
- **repos**: `app/repos/base.py` holds every record type and one `Protocol` per repository.
  `app/repos/pg/` implements them on SQLAlchemy Core; `tables.py` is the schema Alembic diffs
  against. `app/repos/scylla/` is an empty placeholder for a second backend, which is why
  `tests/repos/` are contract tests parametrized by backend (the `world` fixture).
- **views** (`app/views/`): frozen dataclasses subclassing `View`, with no database access. Each
  names a `template` and implements `to_json()`.

`Rendered` in `app/controllers/render.py` is the app's response class and does content
negotiation: one handler serves both HTML and JSON. JSON is chosen by a `.json` path suffix
(stripped before routing, so no extra routes are registered), `api_type=json` in the query or form,
`Accept: application/json`, or any GET under `/api/`. POST handlers return a `FormResult`, which
becomes a 303 redirect for browsers or a `{"json": {"errors": […]}}` envelope for JS/API clients.
`Page` views have no JSON form. Logged-out GETs get `Cache-Control: public, max-age=60`.

Errors are raised as `InaError.of(ErrorCode.X, 'field')` (`app/errors.py`) and rendered by the
exception handlers in `app/controllers/errors.py`.

Each request is one DB transaction (`db.transaction_middleware`), committed just before the
response starts and rolled back on any exception.

### API shapes

`app/views/shapes.py` lists the exact `data` fields for each kind of thing. `test_shapes` checks the
API against them, and the OpenAPI document served at `/dev/api/openapi` is built from them plus
the routes and their scopes. Litestar's own OpenAPI generation is disabled. Adding a JSON field means
updating `shapes.py`.

### Background jobs

Dramatiq actors live in `app/jobs/` (queues: scores, trees, inbox, mail, bouncer, media, search).
Messages carry fullname strings, never objects. Actors reload what they need and must be safe to
replay. Vote and comment score columns are rewritten by the `scores` job, not inline when a vote
is cast. Actors get their engine, Redis and other clients from `app/jobs/context.py`.

In tests, the autouse `published` fixture captures messages instead of sending them to RabbitMQ.
`tests.helpers.run_published` runs them in order. **A new actor must be added to the `actors` map
in `run_published`** or tests that drain the queue will fail.

### Redis cache

Nothing in Redis is authoritative (`app/infra/cache.py`). Things are cached by fullname. Listings
are cached under a per-scope generation counter, so `cache.bump(scope)` invalidates them. Values
are msgspec JSON; **bump `KEY_VERSION` in `app/infra/redis.py` when a cached record's shape
changes** instead of flushing.

### Text

User Markdown is rendered once, on write, with reddit's snudown (a C extension vendored in
`vendor/snudown` and built by uv, since PyPI's `snudown` is an empty placeholder) and then
sanitized through nh3. The HTML is stored alongside the source. Community stylesheets are parsed and
filtered in `app/text/stylesheet.py`. `app/ids.py` is the only place that encodes or decodes base36
fullnames.

### Front end

Templates are Jinja in `app/templates/` (`macros/` and `fragments/` for shared pieces). There is
no `url_for`: URLs are written out as literal r2-style paths. The CSP allows scripts only from
`'self'`, so no inline `<script>` or event-handler attributes. All of `static/css/*.css` is
concatenated in filename order (hence the numeric prefixes), minified and served as one hashed
bundle at `/assets/site.<hash>.css`.

## Tests

- `tests/__init__.py` forces test-only settings before `app` is imported: database `ina_test`,
  Redis db 1, search prefix `ina_test`, bucket `ina-test`, thumbnails off, cheap password hashing.
  `INA_TEST_DATABASE_URL` and `INA_TEST_REDIS_URL` override the first two.
- Migrations run once per session; every test truncates all tables and flushes Redis before
  and after it runs.
- Warnings are errors (`filterwarnings = ["error"]`). pytest-asyncio is in auto mode with a
  session-scoped loop.
- Controller tests drive the app through `client`/`other_client` (separate cookie jars) using the
  helpers in `tests/helpers.py` (`register`, `post_json`, `codes`). The `server` fixture serves
  canned pages for thumbnail and fetch tests.

## Conventions

- Configuration is `app/settings.py`: env vars prefixed `INA_`, also read from `.env`.
- Ruff runs with `select = ["ALL"]`, single quotes, line length 100, and
  `from __future__ import annotations` required in every module. mypy is strict over `app`,
  `migrations`, `scripts` and `tests`. Stubs for snudown and tinycss2 are in `stubs/`.
- Controllers keep handler annotation imports at runtime (the TC rules are disabled there),
  because Litestar resolves signatures at runtime. Don't move those imports under `TYPE_CHECKING`.
- Docstrings and comments explain *why*, in plain sentences. They're not required on every name.
- Commits follow Conventional Commits, enforced by commitlint (`.commitlintrc.json`). Scope, when
  given, must be one of: web, api, views, services, repos, jobs, search, cache, markdown, css,
  frontend, db, auth, mod, infra, deps. Subject ≤ 72 chars, body lines ≤ 100.
- `develop` is the integration branch. CI runs on pushes to it and on pull requests.
